# Scenario-Based Q&A — Classification Algorithms

**Situation**: Your fraud-detection model reports 98% accuracy, and the business team says it's still catching almost no real fraud and generating a flood of complaints from legitimate customers being blocked. What's wrong and what do you do?
**Answer**: With fraud typically at 1-2% prevalence, a model predicting "not fraud" for everyone already gets ~98-99% accuracy while catching zero fraud — the classic accuracy paradox on imbalanced data. I'd switch the primary metric to precision/recall/F1 or PR-AUC (not ROC-AUC or accuracy), inspect the confusion matrix directly, and check the classification threshold — it's likely tuned for overall accuracy rather than business cost of false negatives (missed fraud) vs. false positives (blocked legitimate customers). I'd also apply class weighting or resampling (SMOTE, undersampling) during training and set the decision threshold based on the actual cost ratio of the two error types, not the default 0.5.

**Situation**: A teammate wants to use k-NN for real-time product recommendations on a catalog of 50 million SKUs with 300+ engineered features per item.
**Answer**: Naive k-NN doesn't scale — it's O(n) per query at inference with no training phase, and 300 raw features suffer from the curse of dimensionality where distances become less meaningful. I'd recommend dimensionality reduction (PCA or a learned embedding) to shrink to a few dozen dimensions, then use an approximate nearest-neighbor index (FAISS, HNSW, or ScaNN) instead of brute-force k-NN, and pre-compute/cache embeddings offline so the online path is just an index lookup, not a full distance computation.

**Situation**: You trained an SVM with an RBF kernel that achieves 99.5% training accuracy but only 71% test accuracy.
**Answer**: This is overfitting driven by an overly flexible decision boundary — likely `gamma` is too high (each point's influence is too local, so the boundary wiggles around individual training points) and/or `C` is too high (too little tolerance for margin violations, so the model fits noise). I'd run a grid search over C and gamma with cross-validation, favoring the combination that maximizes validation performance rather than training accuracy, and consider whether a simpler kernel (linear, or polynomial degree 2) is sufficient given the data.

**Situation**: Your logistic regression model for churn prediction has strong AUC (0.85) but the business complains that when it says "80% chance of churn," historically only about 50% of those customers actually churn.
**Answer**: This is a calibration problem, not a discrimination problem — the model ranks customers correctly (good AUC) but its probability outputs don't match observed frequencies. This is common when class weighting, oversampling, or a decision-boundary-focused model (like SVM) was used without recalibration. I'd plot a reliability diagram, compute Brier score, and apply Platt scaling or isotonic regression to remap raw scores to well-calibrated probabilities, especially important if downstream logic (e.g., "auto-offer a discount if churn probability > 70%") depends on those exact numbers.

**Situation**: A decision tree trained on customer data for loan approval reaches 100% training accuracy but the compliance team flags that some leaf nodes contain only 1-2 customers with oddly specific rules (e.g., "approve if income = $52,341.17").
**Answer**: This is a textbook unpruned, overfit tree memorizing individual rows instead of learning generalizable patterns — which is also a compliance and fairness risk since such rules aren't defensible or reproducible on new applicants. I'd apply pre-pruning (`max_depth`, `min_samples_leaf`) or post-pruning via cost-complexity pruning (`ccp_alpha` tuned by cross-validation), and validate the pruned tree's rules are both simpler and hold up on a held-out test set, which also makes the model far easier to explain to auditors.

**Situation**: You need to classify support tickets into 40 categories, and a colleague proposes training 40 separate One-vs-Rest logistic regression models.
**Answer**: OvR works but has a real downside here — each binary classifier sees a heavily imbalanced problem (1 category vs. the other 39 combined), and calibration/thresholds across 40 independently-trained models can be inconsistent, making the "pick highest score" comparison across models unreliable. I'd consider a native multi-class approach instead (softmax/multinomial logistic regression, or a gradient-boosted multi-class model), which is trained on a single coherent objective across all classes and tends to produce better-calibrated, comparable per-class probabilities at this class count.

**Situation**: Your team is deciding between Naive Bayes and a linear SVM for a real-time email spam filter that must classify each message in under 5ms with periodic retraining on millions of new emails daily.
**Answer**: Both are fast at inference, but Naive Bayes trains in closed form (just counting/frequency statistics) which makes daily retraining on millions of emails trivially cheap, while linear SVM requires an iterative optimization that's more expensive to retrain at that frequency. Given the latency and retraining-frequency constraints (not raw peak accuracy), I'd lean Naive Bayes as the production default, and possibly keep a periodically-retrained linear SVM as an offline champion/challenger to validate Naive Bayes isn't leaving significant accuracy on the table given its independence assumption.
